## 1. Global Error Response Envelope

All API endpoints across the backend must strictly return errors adhering to the canonical envelope schema. No raw database exceptions, uncaught tracebacks, or non-standard payloads may ever be returned to the client.

### 1.1 JSON Schema

```json
{
  "error": {
    "code": "ERROR_CODE_STRING",
    "message": "Human-readable summary of the error.",
    "details": [
      {
        "field": "optional_field_name",
        "value": "optional_rejected_value",
        "issue": "Specific explanation of what was invalid."
      }
    ],
    "requestId": "req_01HXYZ123456789ABCDEFG"
  }
}
```

### 1.2 Envelope Attributes

- `code` (`str`): An uppercase, snake_case machine-readable identifier uniquely designating the error category.
- `message` (`str`): A clean, human-readable description appropriate for end-user display.
- `details` (`list[dict]`): Optional array of field-level validation errors, conflict diagnostics, or row-level CSV violations. Empty list `[]` if not applicable.
- `requestId` (`str`): The unique correlation ID generated by the backend `RequestIDMiddleware` (or echoed from the `X-Request-ID` header) to facilitate tracing in server logs without exposing internal system internals.

## 2. Complete Error Code Registry

The following registry enumerates all standardized error codes across the system, their corresponding HTTP status codes, and their user-facing messages.

| Error Code | HTTP Status | User-Facing Message | Typical Cause / Trigger |
|---|---|---|---|
| `UNAUTHORIZED` | 401 | Authentication required or session expired. Please log in. | Missing, invalid, or expired JWT token. |
| `FORBIDDEN` | 403 | You do not have permission to perform this action. | User role lacks capability or department scope does not match. |
| `STUDENT_ACCESS_DENIED` | 403 | You are only authorized to access your own academic records. | Student user attempted to query another student's timetable. |
| `INVALID_CREDENTIALS` | 401 | Invalid email or password. | Login credential mismatch (constant-time evaluation). |
| `ACCOUNT_INACTIVE` | 403 | This account has been deactivated. Please contact an administrator. | User status is `inactive` or `archived`. |
| `ACCOUNT_LOCKED` | 429 | Account temporarily locked due to excessive failed login attempts. | Brute-force protection threshold exceeded. |
| `INVALID_CSV` | 400 | The uploaded file is not a valid CSV or has incorrect headers. | Non-CSV MIME type, corrupt bytes, missing required column headers. |
| `CSV_FILE_TOO_LARGE` | 413 | The uploaded file exceeds the maximum allowed size limit. | File upload exceeds configured maximum byte limit (e.g., 10MB). |
| `CSV_TOO_MANY_ROWS` | 400 | The uploaded CSV exceeds the maximum allowed row limit. | File exceeds max row count limit (e.g., 50,000 rows). |
| `DUPLICATE_STUDENT_IDS` | 422 | Duplicate student identifiers were found in the uploaded data. | Multiple rows in CSV contain the identical `student_number`. |
| `DUPLICATE_SUBJECT_CODES` | 422 | Duplicate subject codes were found in the uploaded data. | Multiple rows contain the identical `subject_code`. |
| `UNKNOWN_STUDENT_REFERENCES`| 422 | The import references student IDs that do not exist in the database. | Enrollment CSV contains `student_id` not found in `students`. |
| `UNKNOWN_SUBJECT_REFERENCES`| 422 | The import references subject codes that do not exist in the catalog. | Enrollment CSV contains `subject_code` not found in `subjects`. |
| `EMPTY_ENROLLMENT_DATA` | 400 | No active student enrollments were found for this scheduling cycle. | Graph construction or generation attempted on cycle without enrollments. |
| `NO_EXAMS_IN_CYCLE` | 400 | There are no active examinations associated with this cycle. | Generation attempted on cycle with zero synced exams. |
| `INVALID_DATES` | 422 | The specified calendar date range is invalid. | Date formatting invalid or outside acceptable calendar limits. |
| `END_BEFORE_START` | 422 | The cycle end date cannot be earlier than the start date. | `endDate < startDate`. |
| `OVERLAPPING_SESSIONS` | 422 | Daily examination sessions cannot have overlapping time intervals. | Session window start/end overlaps another session. |
| `NO_AVAILABLE_SLOTS` | 422 | No enabled time slots exist within the configured cycle calendar. | All dates excluded, all sessions disabled, or slots not generated. |
| `SLOT_TOO_SHORT` | 422 | One or more examinations have a duration exceeding all available time slots. | `exam.duration_minutes > max(slot.duration_minutes)`. |
| `NO_SLOTS_GENERATED` | 400 | Calendar time slots have not been generated for this cycle yet. | Graph coloring or scheduling requested before slot generation. |
| `GRAPH_NOT_FOUND` | 404 | No conflict graph snapshot exists for this scheduling cycle. | Scheduling run requested before building conflict graph. |
| `GRAPH_STALE` | 409 | The conflict graph is stale because student enrollment data has changed. | Enrollment or exam modifications bumped cycle `data_version`. |
| `SCHEDULE_STALE` | 409 | This candidate schedule is based on outdated enrollment or graph data. | Attempting to review or publish a schedule built from stale graph. |
| `INVALID_LOCKED_ASSIGNMENTS`| 422 | One or more locked exam assignments violate calendar or duration constraints.| Locked assignment placed in holiday, disabled slot, or incompatible slot. |
| `CONFLICTING_LOCKED_EXAMS` | 409 | Two or more locked exams assigned to the same slot have student conflicts. | Precoloring check found adjacent vertices locked to the same slot. |
| `INVALID_COLORING` | 500 | An internal algorithm error produced an improper graph coloring. | Independent validator detected adjacent vertices sharing a color. |
| `SCHEDULE_VALIDATION_FAILURE`| 422 | The schedule violates one or more hard examination constraints. | Validation failed hard constraints (student clash, duplicate exam). |
| `INSUFFICIENT_SLOTS` | 422 | Insufficient time slots available to schedule all non-conflicting exams. | Graph chromatic number $\chi(G)$ exceeds available eligible slots. |
| `EXAM_LOCKED` | 409 | This examination is locked and cannot be moved until unlocked. | Manual move attempt on an exam with `locked = true`. |
| `INVALID_MOVE` | 422 | Moving this examination to the requested slot introduces a student conflict. | Preview or patch move creates a shared-student collision. |
| `CONCURRENT_MODIFICATION` | 409 | The schedule was modified by another user. Please refresh and try again. | Optimistic concurrency mismatch on `row_version` / `updated_at`. |
| `SCHEDULE_ALREADY_PUBLISHED`| 409 | This schedule is published and cannot be modified. | Attempted mutation of an immutable `Published` schedule version. |
| `PUBLISH_VALIDATION_FAILED`| 422 | The schedule cannot be published because it has unresolved conflicts. | Publish gate validation failed one or more hard constraints. |
| `RATE_LIMIT_EXCEEDED` | 429 | Too many requests. Please wait before retrying. | Endpoint rate limiter triggered. |
| `GENERATION_TIMEOUT` | 504 | Schedule generation exceeded the maximum execution time limit. | Synchronous computation exceeded timeout threshold (e.g., 15s). |
| `INTERNAL_SERVER_ERROR` | 500 | An unexpected internal error occurred. Please contact support. | Unhandled exception (sanitized in production, full trace logged). |

## 3. Implementation Blueprint

In FastAPI, the centralized exception handler translates:
1. `RequestValidationError` (Pydantic) -> HTTP 422 with `code: "VALIDATION_ERROR"`.
2. `DomainException` (custom base class) -> Appropriate HTTP status code and registered `code`.
3. `SQLAlchemyError` -> HTTP 500 with `code: "DATABASE_FAILURE"` (raw SQL suppressed).
4. `Exception` -> HTTP 500 with `code: "INTERNAL_SERVER_ERROR"` and correlation `requestId`.
